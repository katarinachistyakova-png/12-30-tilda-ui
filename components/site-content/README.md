# Контент сайта 12:30

`components/site-content/content.js` — временный источник редакционного контента.
В нём только два раздела:

- `featuredStory` — одна вещь с историей на главной;
- `bloggers` — блогеры и стилисты и вещи-превью каждого.

Вёрстка и стили лежат в компонентах. Чтобы поменять контент, HTML и CSS трогать не нужно.

## Кто за что отвечает

| Tilda — источник товаров | content.js — только выбор |
|---|---|
| товар, название, бренд | какую одну историю показать на главной |
| цена | каких блогеров показать |
| фотографии товара | какие вещи-превью показать у блогера |
| остаток | |
| категории, SKU | |
| страница товара | |

Второй базы каталога нет и быть не должно. Товарная выдача главной читает Tilda напрямую.
Всё, что написано о товаре здесь (название, цена, фото, ссылка у истории и у вещей-превью), —
копия из Tilda для показа, а не новый источник.

**До подключения CRM:** если у вещи из `featuredStory` в Tilda изменились цена или название,
их нужно вручную поправить в `content.js`. Автоматической синхронизации нет.
Если вещь продана — заменить историю или поставить `featuredStory: null`.

# CONTENT MANAGEMENT NOW

Все действия — в одном файле `content.js`. После правки сохраните файл и обновите страницу.

## A. Как поменять историю на главной

Найдите блок `featuredStory` и замените значения:

| Что | Откуда взять |
|---|---|
| `productUid` | номер товара в Tilda (Tilda UID) |
| `brand` | бренд |
| `title` | название товара, как в Tilda |
| `quote` | слова продавца из описания товара. Без кавычек — их поставит сайт |
| `price` | цена числом: `5300` |
| `image` | фото из галереи товара |
| `productUrl` | адрес страницы товара, скопированный из браузера |
| `section` | `women` или `men` — в каком разделе главной показывать |

Необязательные: `imageAlt` (что на фото, одной фразой) и `imageFocus`
(какая часть фото видна: `50% 0%` — верх, `50% 100%` — низ).

Правила:

- историю не придумывать и не переписывать. Можно убрать фразу о состоянии вещи;
- адрес товара не придумывать;
- вещь должна быть в наличии;
- лучше всего работает живое фото: вещь на человеке, на улице, дома.
  Если есть только фото на белом фоне, попросите снимок у продавца или выберите другую историю.
  Изображения не генерировать, стоки не брать.

Убрать историю с главной совсем: `featuredStory: null`.

## B. Как добавить нового блогера

В списке `bloggers` скопируйте блок любого блогера целиком — от `{` до `}` —
вставьте после последнего через запятую и замените значения:

| Что | Что это |
|---|---|
| `id` | короткое имя латиницей без пробелов |
| `name` | имя, как оно пишется на сайте |
| `photo` | фото человека |
| `shortDescription` | одна строка про стиль |
| `telegramUrl` | ссылка на Telegram |
| `catalogUrl` | ссылка на все его вещи в каталоге |
| `showOnHome` | `true` — показывать на главной, `false` — нет |
| `homeOrder` | каким по счёту на главной: 1, 2… |
| `featuredProducts` | 3–4 вещи-превью (см. пункт E) |

Необязательные: `nameGenitive` — имя для ссылки «Все вещи … →» («Маруси», «Анны»);
`photoFocus` — какая часть фото видна; `description` — описание подлиннее для страницы всех блогеров.

Главная показывает не больше двух человек. Нового блогера добавляйте
с `showOnHome: false`, если на главной уже двое.

## C. Как убрать блогера с главной, не удаляя его

У этого блогера поставьте `showOnHome: false`. Его данные останутся в файле,
и он по-прежнему будет на странице всех блогеров.

## D. Как поменять порядок блогеров на главной

Поменяйте числа `homeOrder`. У кого `1` — стоит первым, у кого `2` — вторым.

## E. Как заменить вещи-превью

У блогера в списке `featuredProducts` замените строку вещи. В каждой строке:

| Что | Откуда |
|---|---|
| `productUid` | номер товара в Tilda |
| `title` | название вещи |
| `image` | фото вещи |
| `productUrl` | адрес страницы товара из браузера |

Порядок строк — порядок картинок на сайте. Показываются первые четыре.

# FUTURE CRM MIGRATION

Не реализовано. Это план следующего этапа.

```
СЕЙЧАС:   content.js  →  главная
ПОТОМ:    CRM  →  открытый адрес только для чтения  →  главная
```

Сайт уже готов к замене источника. Главная получает данные в одном месте
и не знает, откуда они пришли. Когда CRM начнёт отдавать те же данные по адресу,
этот адрес указывается в одном атрибуте блока главной (`data-s1230-content-url`),
а `content.js` отключается. Вёрстка, стили и раскладка не меняются.

CRM должна отдавать данные в том же виде:

```json
{ "featuredStory": { … }, "bloggers": [ { … }, { … } ] }
```

Что станет полями CRM:

| Сейчас в content.js | В CRM |
|---|---|
| `featuredStory.productUid` | выбор товара для истории на главной |
| `featuredStory.quote` | история продавца у товара |
| `featuredStory.image`, `imageFocus` | выбор фото для главной и его кадрирование |
| `featuredStory.section` | раздел: женское или мужское |
| `brand`, `title`, `price`, `productUrl` | не вводятся вручную: CRM берёт их из товара Tilda |
| `bloggers[]` | карточка блогера: имя, фото, описание, Telegram, ссылка на его вещи |
| `showOnHome`, `homeOrder` | галочка «показывать на главной» и порядок |
| `featuredProducts[]` | выбор 3–4 товаров блогера для превью |

Картинки из CRM должны приходить полными адресами (`https://…`) — сайт берёт их как есть.

# PARTNER ANALYTICS

Цифры по блогерам и стилистам — на основе той Яндекс.Метрики, что уже стоит на сайте.
Нового счётчика, базы и сервера нет. Код — `partner-analytics.js` рядом с `content.js`.

## Что считаем

- **Показ** — блок человека был виден хотя бы наполовину не меньше секунды.
  Один человек в одном месте — один показ за открытие страницы, сколько бы ни листали вверх-вниз.
- **Клик** — нажатие на фото, имя, «Все вещи …», маленькую вещь или Telegram.
- **Намерение сотрудничать** — нажатие на «Хочу сотрудничать →» или «Оставить заявку →».
  Это не клик по партнёру, поэтому у него своя цель.

Чего **не** считаем: продажи. У 12:30 нет надёжного признака завершённой продажи, поэтому
«этот блогер принёс N продаж» и «выручка Маруси» из этих данных не получить. Только показы,
клики, интерес к вещам, переходы в каталог и в Telegram, намерение сотрудничать.

## Цели в Метрике

Создать в существующем счётчике: «Цели» → «Добавить цель» → «JavaScript-событие».
Ровно три, на всех партнёров и все места:

| Идентификатор цели | Когда срабатывает |
|---|---|
| `partner_impression` | человека увидели |
| `partner_click` | нажали на блок человека |
| `collaboration_cta_click` | нажали «Хочу сотрудничать» / «Оставить заявку» |

Отдельных целей на людей, вещи и места не создаём — различия идут параметрами.
`person_id` — стабильный ключ: `curlyruboy`, `marusia-azdrakhabova`. После запуска не менять.

## Места (`placement`)

| placement | Где | Состояние |
|---|---|---|
| `homepage_bloggers` | блок на главной | работает |
| `collaboration` | «С кем мы уже сотрудничаем» и кнопки на /collaboration | работает в `collaboration-v2` |
| `bloggers_showcase` | страница /bloggersshowcase | работает в заготовке `bloggers-showcase`; в продакшен-странице Леры — по спецификации ниже |
| `featured_partner`, `catalog_editorial` | на будущее | — |

Новое место — это просто новое имя во втором аргументе `attach`/`observe`. Новых целей и кода нет.

## Параметры

`partner_impression` и `partner_click`:

| Параметр | Пример | Когда есть |
|---|---|---|
| `person_id` | `curlyruboy` | всегда |
| `person_name` | `Curlyruboy` | всегда |
| `placement` | `homepage_bloggers` | всегда |
| `action` | `impression` / `click` | всегда |
| `target` | `catalog` / `product` / `telegram` | у кликов |
| `source` | `photo` / `name` / `all_items` / `preview` / `telegram` | у кликов |
| `product_uid`, `product_title` | `202463240463`, `Кепка` | клик по вещи |

`collaboration_cta_click`:

| Параметр | Пример |
|---|---|
| `placement` | `collaboration` |
| `source` | `hero` / `final` (у каждой кнопки своё место) |
| `target` | `application` |

Персональные данные посетителей не передаются: ни имён, ни почты, ни телефонов, ни Telegram.

## Как подключить к странице (спецификация разметки)

Помощник ничего не знает про вёрстку. Он читает атрибуты `data-s1230-*`, которые не влияют на внешний вид:

| Атрибут | Где | Значение |
|---|---|---|
| `data-s1230-person` | карточка человека | `id` из `content.js` |
| `data-s1230-name` | карточка человека | имя для отчётов |
| `data-s1230-target` | ссылка внутри карточки | `catalog` / `product` / `telegram` |
| `data-s1230-source` | та же ссылка | `photo` / `name` / `all_items` / `preview` / `telegram` |
| `data-s1230-product` | ссылка на вещь | `productUid` |
| `data-s1230-cta` | кнопка «Хочу сотрудничать» | где стоит: `hero`, `final`, … |

Название вещи берётся из `aria-label` её ссылки. После разметки два вызова:

```
s1230PartnerAnalytics.attach(контейнер, 'placement');   // клики
s1230PartnerAnalytics.observe(контейнер, 'placement');  // показы, после отрисовки карточек
```

Примеры разметки: `components/bloggers-showcase/index.html` (`bloggers_showcase`),
`components/collaboration-v2/index.html` (`collaboration`).

**Продакшен /bloggersshowcase (страница Леры).** Не заменяем и не перерисовываем. Чтобы подключить:
проставить атрибуты из таблицы на её блоки (для каждого человека: карточка, фото, имя,
«Все вещи», каждая вещь, Telegram), затем в T123 на этой странице вызвать `attach` и `observe` с
`bloggers_showcase`. Пока её разметки в проекте нет, как именно проставить атрибуты в Tilda,
решим, когда посмотрим страницу.

## Как посмотреть одного блогера в Метрике

«Отчёты» → «Параметры визитов» → `person_id` → нужный человек; дальше по `placement`, `target`,
`source`, `product_title`. Или сегмент: цель `partner_click` + `person_id`.

**Ограничение.** Обычные отчёты Метрики привязывают параметры к визиту, а не к отдельному событию.
Если за один визит человек увидел обоих блогеров и нажал на одного, оба `person_id` окажутся в одном
визите. Для приблизительных сравнений этого хватает, для точных цифр в предложении партнёру — нет.
Точные цифры дают события из Logs API (ниже).

# PARTNER PERFORMANCE REPORT (спецификация)

Отчёт по одному партнёру за выбранный период. Интерфейса пока нет, это структура данных.

```
Curlyruboy · сентябрь 2026

Всего
  Показы                    Impressions
  Уникальные посетители     Unique visitors   (люди, которые видели блок)
  Клики                     Total clicks
  CTR                       Clicks / Impressions

Клики по типу
  В каталог                 target = catalog   (фото, имя, «Все вещи»)
  На вещи                   target = product
  В Telegram                target = telegram

По местам                   Impressions · Clicks · CTR
  homepage_bloggers
  bloggers_showcase
  collaboration

Самые кликабельные вещи     топ-3 по product_uid / product_title
```

Как считаются:

- **Impressions** — число `partner_impression` с этим `person_id`. Один человек на одной странице
  за открытие — один показ, значит это «открытий страницы, где блок был виден», не «пролистываний».
- **Unique visitors** — разные посетители среди этих показов (`clientID`).
- **Total clicks** — число `partner_click` с этим `person_id`.
- **CTR** = Total clicks / Impressions, считается и по каждому месту отдельно.
- **Top products** — `partner_click` с `target = product`, сгруппированные по `product_uid`.

Чего в отчёте нет и не будет без отдельного подтверждения продаж: заказов и выручки партнёра.
`collaboration_cta_click` в отчёт партнёра не входит: это спрос на программу в целом.

# LOGS API (заготовка на будущее, сейчас не реализовано)

Логи Метрики — выгрузка каждого события отдельной строкой. Нужны, когда точность важна: цифры
уходят в коммерческое предложение, и спорить о том, кому какой клик принадлежит, нельзя.
Не строим ни выгрузку, ни базу, ни расписание — только фиксируем, что понадобится.

**Источник:** хиты (`hits`). Цели `reachGoal` приходят там как искусственные хиты.
**Фильтр:** цели `partner_impression`, `partner_click`, `collaboration_cta_click`.
**Поля** (названия сверить с документацией Logs API при реализации):
дата и время события, идентификатор посетителя (`clientID`), идентификатор события (`watchID`),
адрес страницы, цель, параметры события — `person_id`, `placement`, `target`, `source`,
`product_uid`, `product_title`.

Как считать по строкам:
- Impressions = строки `partner_impression`, сгруппированные по `person_id` и `placement`;
- Unique visitors = число разных `clientID` среди них;
- Clicks = строки `partner_click`; CTR = Clicks / Impressions;
- Top products = `partner_click` с `target = product`, по `product_uid`.

Здесь параметры привязаны к событию, а не к визиту, поэтому два блогера в одном визите не смешиваются.

# HOW THIS BECOMES A PAID PLACEMENT PRODUCT

**Сегодня.** Мы бесплатно, по вкусу показываем блогеров и стилистов и копим базовый уровень:
сколько людей видит блок, сколько нажимает, куда.

**Через несколько недель.** Становится понятно, что для блока нормально: типичный CTR,
сколько кликов уходит в каталог, на вещи и в Telegram, чем место на главной отличается от
страницы блогеров и /collaboration. Появится сравнение людей между собой и с обычным уровнем.

**Что можно будет продавать:**
- место на главной (featured placement);
- присутствие на странице блогеров;
- усиленную подборку вещей (больше превью, выше в блоке);
- дополнительный период размещения.

**Какие цифры позволят назначить цену:** показы в месяц на место, уникальные посетители,
CTR места и человека, доля кликов в каталог и на вещи, переходы в Telegram, самые кликабельные вещи.
Цену из них можно обосновать только после того, как накопится несколько недель данных.
Цены сейчас не придумываем.

Что мы не обещаем партнёрам: продажи и выручку. Есть «увидели» и «нажали», завершённой продажи
в данных нет.

# Если Метрика не нашлась

Счётчик ищется автоматически среди подключённых Tilda. Если не найден, укажите его вручную
в `content.js`: `analytics: { counterId: 12345678 }` внутри `window.s1230Content`.
Пока счётчика нет, страницы работают как обычно, просто ничего не считается.
