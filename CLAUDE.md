# 12-30-tilda-ui

Отдельный frontend-проект сайта ресейл-проекта **12:30** на Tilda.
Здесь создаются готовые страницы и UI-компоненты для вставки в Tilda.

## Границы проекта

- Проект **НЕ связан с CRM**.
- **Никогда не изменять файлы проекта `12-30-crm`** — ни читать с целью правки, ни редактировать, ни коммитить туда.

## Технологии

- Только обычные HTML, CSS и JavaScript.
- Без React, Vue и других frontend-фреймворков.
- Не подключать внешние библиотеки без необходимости.

## Правила компонентов

- Каждый компонент независимый: не зависит от других компонентов и не влияет на них.
- Все CSS-классы начинаются с префикса `s1230-`.
- Не переопределять глобальные стили Tilda: `body`, `html`, `a`, `button`, `h1`–`h6`, `p`, `img`, `*` и т. п. Все стили — только через классы `s1230-`.
- JavaScript изолирован (IIFE или аналог), без глобальных переменных; DOM ищется внутри корневого элемента компонента.
- Обязательно делать desktop и mobile версии (адаптив).
- Код должен подходить для вставки в HTML-блок Tilda **T123**.
- По возможности HTML + CSS + JS одного компонента хранить в одном `index.html`.
- Каждая задача легко удаляется и не ломает остальные блоки сайта.

## Структура

```
components/<component-name>/index.html
```

## Процесс

1. Реализовать компонент в `components/<component-name>/index.html`.
2. После реализации объяснить:
   - как вставить результат в Tilda (блок T123);
   - как проверить (desktop, mobile, отсутствие конфликтов с другими блоками).
3. После законченной задачи сделать `git commit`.

## Product philosophy: Huggable

Постоянный раздел. Эта философия — не слоган, а **фильтр для каждого продуктового решения**: UX, UI, копирайта и поведения компонентов.

12:30 строится вокруг идеи **Huggable**.

Huggable — значит свой, простой, понятный. Тот, с которым хочется идти вперёд и менять устоявшиеся правила. Таким может быть и человек, и команда, и бизнес.

**Ключевая формула бренда:** Будущее, к которому хочется прикасаться.

**Пять опор:** человечность + технология + изменения + вкус + доверие.

### UX

- Пользователь не должен разбираться, как устроена система.
- Сложная логика должна ощущаться простой.
- Там, где можно убрать шаг, поле, выбор или сомнение — убираем.
- Интерфейс должен помогать двигаться вперёд, а не требовать изучения.
- Не заставлять человека чувствовать, что он «делает что-то неправильно».
- Ошибки и неидеальные данные должны обрабатываться мягко.
- Важнее помочь закончить действие, чем добиться идеального ввода.
- Любая новая технология должна давать пользователю ощущение облегчения, а не сложности.

### UI

- Чисто, но не стерильно.
- Современно, но не футуристично ради футуризма.
- Вкусно, но не снобски.
- Минимализм не должен превращаться в холодность.
- Не использовать визуальные паттерны типичного SaaS-интерфейса без необходимости.
- Не делать интерфейс «дорогим» за счёт декоративности.
- Визуальная уверенность должна идти из типографики, композиции, воздуха и хороших изображений.
- Интерфейс должен казаться тактильным и живым — это часть идеи «будущее, к которому хочется прикасаться».

### Копирайт

- Писать по-человечески.
- Не использовать канцелярит.
- Не использовать корпоративный язык.
- Не быть нарочито «дружелюбными» или инфантильными.
- Не поучать пользователя.
- Не заставлять его чувствовать себя неопытным.
- Объяснять, зачем что-то нужно, если это снимает сомнение.
- Давать ощущение, что 12:30 находится рядом и поможет, но не навязывается.
- Текст должен быть коротким, точным и естественным.

### Технология

Технологичность 12:30 не должна проявляться словами «AI», «automation», «smart» и подобными ярлыками. Она должна ощущаться через поведение продукта:

- данные не приходится вводить дважды;
- система помнит контекст;
- нужная информация появляется вовремя;
- ручной труд пользователя сокращается;
- интерфейс предугадывает следующий шаг;
- взаимодействие становится быстрее и спокойнее.

Хорошая технология здесь почти невидима.

### Изменения

12:30 хочет менять привычные правила потребления и ресейла, но не должен говорить об этом тяжело или манифестно в каждом интерфейсе. Изменения должны ощущаться через сам продукт:

- продавать вещь легко;
- покупать ресейл естественно;
- история вещи имеет ценность;
- новая вещь не обязательно должна быть новой;
- циркулярность не должна ощущаться как компромисс.

### Вкус

Вкус — это кураторство, редактура и чувство меры. Не использовать вкус как инструмент исключения или снобизма. Не создавать ощущение:

- «мы лучше знаем»;
- «вы недостаточно разбираетесь»;
- «сюда подходят только правильные вещи или правильные люди».

12:30 должен быть кураторским, но открытым.

### Доверие

Доверие строится через:

- ясность;
- честные ожидания;
- понятные условия;
- прозрачность цены и комиссии;
- доступность контакта;
- отсутствие скрытых действий;
- спокойный язык;
- предсказуемое поведение интерфейса.

Если есть выбор между эффектным решением и решением, которое вызывает больше доверия, — выбирать доверие.

### Проверка любого решения

Перед тем как реализовать новый экран, компонент или текст, проверить его по пяти вопросам:

1. Это делает опыт более человечным?
2. Технология здесь действительно упрощает жизнь?
3. Это помогает двигаться вперёд и менять старый сценарий, а не просто украшает его?
4. В решении есть вкус и чувство меры?
5. Оно усиливает доверие?

Если хотя бы по двум пунктам ответ «нет» — решение нужно пересмотреть.
